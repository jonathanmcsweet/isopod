usage: isopod secret set <NAME> | ls | rm <NAME>
  set   store a value (read from stdin or a hidden prompt — never argv)
  ls    list stored secret names (values are never printed; --json adds the
        backend and per-box attribution)
  rm    delete a stored secret
Inject into a box at create time: isopod create <name> --secret NAME[:path]

What --secret does and does not protect against
  A value is kept on the host (OS keychain when available) and streamed over the
  box's SSH channel into a tmpfs at run time. It never reaches an image layer,
  argv, the container environment, '$ENGINE inspect', a reconfigure snapshot or
  an 'isopod export' tarball, and a stopped box holds none of it.
  It IS readable by whatever runs in the box. The file is owned by the box user,
  which is the account your code and any agent run as — and on a sudo box that
  account can reach root as well. --secret protects a credential from the image
  and from the host's tooling, NOT from the workload you handed it to.
