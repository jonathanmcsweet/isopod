usage: isopod install <box> <pkg> [<pkg>...]

Install system packages into an existing box from the HOST, as root, without
giving the in-box user sudo. This is the companion to a --no-sudo box: the box
stays locked down (no in-box root a rogue agent could abuse), but you can still
add a forgotten build dependency without recreating it.

Installing a named package this way is safer than opening a root shell and
running the project build: a root shell can be tricked into executing the box's
(agent-controlled) code as root, whereas this only runs the package manager on a
name you chose.

  - Runs the box's package manager (apt-get/apk/dnf) as root, via the engine.
  - Package NAMES only — no paths, options, or version pins (use --dockerfile).
  - The box must be running, and must be a container: a microVM guest can't be
    modified live — bake the package with --dockerfile and recreate.

Installs are EPHEMERAL: they are lost when the box is recreated. For a dependency
you always need, add it to a --dockerfile so it is baked into the image.

Language packages (pip/npm/cargo) usually need no root at all — install them
user-scoped inside the box. Use 'isopod install' for the system packages
(headers, CLI tools, -dev libraries) that genuinely require root.
