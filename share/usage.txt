isopod $ISOPOD_VERSION — isolated AI-coding sandboxes for VSCodium & friends

Usage:
  isopod create <name> [options]      Create and start a new sandbox
  isopod list [--json]                List sandboxes and their status
  isopod info <name> [--json]         Show connection details for a sandbox
  isopod code <name> [--app APP]      Open the sandbox in a new VSCodium window (or APP)
  isopod shell <name> [-- cmd...]     Open a shell (or run cmd) inside the sandbox
  isopod start <name>                 Start a stopped sandbox
  isopod stop <name>                  Stop a running sandbox
  isopod config <name>                Show a box's editable config (config.yaml)
  isopod reconfigure <name> [opts]    Apply new run settings to an existing box
  isopod export <name> [dest]         Copy the workspace OUT (--exclude PAT, --gitignore)
  isopod fetch <name> [target-dir]    Pull the box's git history into a host repo
  isopod remap <name> [target-dir]    Rewrite a box's commit identity after fetch
  isopod copy-in <name> <path>...     Copy more host folders INTO the sandbox
  isopod install <name> <pkg>...      Install system packages into a box (host-mediated, no in-box sudo)
  isopod rm <name> [--force]          Delete a sandbox (container + keys + snapshots)
  isopod gc [--dry-run] [--force]     Remove isopod images no box still references
  isopod egress [status|apply|allow …]  Manage the network egress firewall/proxy
  isopod secret [set|ls|rm] <NAME>    Manage secrets injected into boxes
  isopod doctor                       Check host prerequisites
  isopod help                         Show this help

Secure by default: a box runs in a microVM (its own kernel) when a virtio-net
microVM runtime (kata) and KVM are available, falling back to gVisor then
a plain container; pass --container to force a plain container. (krun is a microVM
too, but its TSI networking stalls bulk data over SSH port-forwards into the box,
which breaks 'isopod code' Remote-SSH — so it is not auto-selected; pass
--runtime krun to use it for shell/copy/export.) Network egress uses the
allow-list by default (only
allow-listed hosts are reachable) — set ISOPOD_EGRESS=off or 'no-egress' in
hardening.conf to turn it off.

Options for create (each accepts both '--opt value' and '--opt=value'):
  --repo <url>          Git repo to clone into the box (https or ssh URL;
                        repeatable). Each clones into its own workspace
                        subfolder, so a box can hold more than one repo.
  --branch <name>       Branch to clone (applies to every --repo)
  --copy <path>         Host folder/file to COPY into the box (repeatable).
                        This is the explicit allowlist — nothing else from
                        the host is ever visible inside the box.
  --color <preset|hex>  Tint the IDE title/status/activity bars so this
                        box's windows are visually distinct. Presets:
                        red orange amber green teal blue purple magenta gray
                        or any hex like '#7e22ce'. Default: auto (rotates).
  --engine <podman|docker>   Container engine (default: podman, else docker)
  --image <ref>         Base image (default: $DEFAULT_BASE_IMAGE).
                        Must be Debian/Ubuntu-based (apt): isopod layers
                        sshd, git, and the in-box user on top of it. Build
                        your own with a Dockerfile to bake in a toolchain.
  --dockerfile <path>   Build this Dockerfile first and use it as the base
                        (isopod then layers sshd/git on top). The standard
                        way to provision a box; mutually exclusive with --image.
  --expose <spec>       Publish a container port to the host on 127.0.0.1
                        (repeatable). <spec> is 'PORT' (same port on host) or
                        'HOSTPORT:CONTAINERPORT', e.g. --expose 3001:3000 makes
                        a server on the box's :3000 reachable at localhost:3001.
  --memory <size>       Memory limit, e.g. 4g
  --cpus <n>            CPU limit, e.g. 2
  --no-sudo             Do not give the in-box user passwordless sudo
  --harden <level>      Kernel-hardening profile: 'default' (on for every box —
                        reduced-surface guest sysctls on microVM boxes) or 'off'.
                        'strict' is reserved for a future release.
  --container           Run as a PLAIN container instead of the default microVM
                        (lower isolation). Use when no microVM runtime/KVM is
                        available, or you accept a shared-kernel sandbox.
  --runtime <name>      Pin a specific OCI runtime (e.g. krun, kata, runsc)
                        instead of auto-selecting. Same effect as ISOPOD_RUNTIME.
                        --container overrides this.
  --dev                 Add the dev/test toolchain (nested podman/docker, the
                        docker group, shellcheck/shfmt/pexpect/nftables) so the
                        box can run isopod's own test suite. Off by default —
                        the lean base has none of this extra attack surface.
  --port <n>            Fixed host port for SSH (default: random free port,
                        bound to 127.0.0.1 only)
  --secret NAME[:path]  Inject secret NAME (stored via 'isopod secret set') into
                        the box at path (default /run/secrets/NAME), repeatable.
                        Values live in a memory-backed tmpfs and are streamed in
                        over SSH — never in the image, env, 'inspect', export
                        tarballs, or reconfigure snapshots. Re-injected on start.

Reconfiguring a box (change run settings without starting over):
  Every box has an editable config at $CONFIG_DIR/boxes/<name>/config.yaml,
  written as a real (engine-correct) Compose service you can read or reuse — but
  isopod owns and parses it and does NOT run it (see the file's header).
  View it with 'isopod config <name>'. Edit a value, or pass flags below, then run
  'isopod reconfigure <name>'. isopod snapshots the box (preserving your workspace
  and installed packages), then recreates the container with the new settings.

Options for reconfigure (or edit config.yaml; each accepts '--opt value' and '--opt=value'):
  --expose <spec>       Replace the box's forwarded ports (repeatable; same form
                        as create's --expose)
  --memory <size>       New memory limit, e.g. 8g (blank clears it)
  --cpus <n>            New CPU limit, e.g. 4 (blank clears it)
  --color <preset|hex>  Re-tint the IDE window

Options for code (each accepts both '--opt value' and '--opt=value'):
  --app <name>          IDE to launch: codium (default), vscodium, cursor,
                        windsurf, code
  --reuse-window        Reuse an already-open IDE window instead of opening a
                        new one. These editors are single-instance, so without
                        this flag isopod passes --new-window to keep each box
                        in its own window.

Options for remap (run after 'isopod fetch'; each accepts '--opt value' and '--opt=value'):
  --name <new name>     New author/committer name to write. Defaults to
                        ISOPOD_GIT_NAME, else host 'git config user.name'.
  --email <new email>   New author/committer email to write. Defaults to
                        ISOPOD_GIT_EMAIL, else host 'git config user.email'.
  --old-email <e>       Identity to rewrite FROM; only commits with this
                        email are touched. Auto-detected from the box if
                        omitted (requires the box to still exist).
  --old-name <n>        Also require this name to match before rewriting.
  --remap-file <file>   Remap many identities at once from a file of
                        'old -> new' lines (e.g. dev@box -> Me <me@real.com>).
                        Overrides the single-pair flags and the default
                        ~/.config/isopod/remap.
  --force, -f           Skip the confirmation prompt.

Network egress isolation (host-enforced; an in-box agent cannot turn it off):
  ON by default in 'allow-list' mode. Load it once with 'sudo isopod egress apply'
  (needs a rootful engine — host bridge). When it can't be enforced (rootless
  engine, proxy/firewall not loaded) a default-on box degrades with a warning:
  allow-list -> lan-deny -> open. Change the mode in ~/.config/isopod/hardening.conf
  (or ISOPOD_EGRESS=...); ISOPOD_EGRESS=off / 'no-egress' turns it off.

  Modes:
   'egress lan-deny'    block box->LAN/host/metadata/internal-DNS; public internet
                        and host->box published ports keep working.
   'egress allow-list'  DEFAULT-DENY egress: a host-side filtering proxy is the
                        box's only route out, and only allow-listed hostnames pass
                        (stops data exfiltration to arbitrary destinations).
  Subcommands:  status, apply (load firewall + start proxy), observe (build the
  allow-list from real traffic), allow <domain>, log [-f], denied, rules.

Secrets (host-stored, injected per box):
  'isopod secret set NAME' stores a value (stdin or hidden prompt — never argv)
  in the OS keychain ('security' on macOS, 'secret-tool' on Linux), falling back
  to a 0600 file under $CONFIG_DIR/secrets. 'secret ls' lists names isopod
  manages (a secret stored outside isopod won't list); 'secret rm' deletes one.
  Secrets are host-global: removing a box does not remove its secrets.

Examples:
  isopod create myproj --repo https://github.com/me/proj --color teal
  isopod create app --repo https://github.com/me/api --repo https://github.com/me/web
  isopod create web --repo https://github.com/me/web --dockerfile ./Dockerfile --expose 3000
  isopod create scratch --copy ~/src/lib-a --copy ~/notes/specs --color '#b3261e'
  isopod code myproj
  isopod export myproj ./myproj-out
  isopod fetch myproj            # from inside your host clone, pulls box history
  isopod remap myproj           # rewrite box commits to your host git identity
  isopod remap myproj --name "Real Name" --email me@real.com   # or override it
  isopod remap myproj --remap-file ~/.config/isopod/remap      # remap many identities
