usage: isopod claude-code <box> [--app TERMINAL] [--attach] [-- args...]

Run Claude Code inside a box. Starts the box if it is stopped, installs Claude
Code if it is not there yet, then opens a new terminal window with a session in
the box's workspace, the way 'isopod code' opens an editor window.

  --app <name>   terminal to open (see the list below); ISOPOD_TERMINAL sets a
                 default. Without either, the first one installed is used.
  --attach       run in THIS window instead of opening a new one, for a headless
                 host or when you would rather keep the session where you are.
  -- args...     passed through to claude, e.g. -- --help

Terminals isopod knows: ghostty, kitty, wezterm, alacritty, gnome-terminal,
konsole, foot, xfce4-terminal, xterm. A name that is not on the list is tried as
a plain command, and a host with no terminal at all falls back to --attach.

The binary is downloaded and its SHA-256 checked on your machine, then copied in
over SSH, so the box never fetches or runs an installer of its own. It goes in as
the box user, not root, and lands wherever 'claude install' puts it.

isopod installs whatever is newest at that moment and then leaves it alone.
Updating afterwards is Claude Code's own job, on your schedule, from inside the
box.

Signing in: isopod offers to store an ANTHROPIC_API_KEY the first time and hands
it to the box in memory, out of sight of the process list. Press enter at that
prompt to skip it and let Claude Code sign you in its own way instead. Change or
remove the stored key with 'isopod secret set ANTHROPIC_API_KEY' and
'isopod secret rm ANTHROPIC_API_KEY'.

On a box using the egress allow-list, isopod prints the hostnames Claude Code
needs and leaves your allow-list alone, since that list is shared by every box on
this host. Offline boxes are refused: the install would work, but Claude Code
could not reach the API from a box with no route out.
